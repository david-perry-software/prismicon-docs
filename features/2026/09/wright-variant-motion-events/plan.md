# Wright variant motion events

## Problem

The Wright variant currently ships only a placeholder motion layer. In `src/variants/wright.js`, `poseWright` returns a generic `{ lift, shear, pulse }` object and `animateWright` drives those three fields — a vertical lift applied to every layer, a horizontal-plane skew, and an accent-width pulse. `paintWright` consumes the same fields (`pose.lift` as a global y-shift, `pose.shear` as a plane-width skew, `pose.pulse` as accent scaling). This is a re-skin of generic transforms, not a Wright architectural language: a state change is not legible as illumination, panel, or structural behavior, and the motion does not preserve the "restrained architecture" reading the family is meant to have.

This plan implements the `wright-variant-motion-events` member of the [Frank Lloyd Wright variant breakdown](../../../../initiatives/2026/09/frank-lloyd-wright-variant/breakdown.md#wright-variant-motion-events), whose brief is: "Preserve geometric identity while making state changes legible through Wright-like motion language rather than generic transforms." It maps prismicon's runtime states and transient events — `idle`, `working`, `waiting`, `done`, `error`, `thinking`, `sending`, `receiving`, `sleeping`, and the internal `settling` (see `src/core.js`) — to restrained, architecture-consistent motion motifs while keeping the static portrait byte-identical.

## Decisions

The user answered all four clarifying questions with `defaults`, accepting the recommended default for each:

1. Motion vocabulary scope (default): each public state gets a distinct, recognizable Wright motion motif drawn from illumination paths, panel pulses, and structural settle/reconstruct; `done` and `error` remain handled by the existing `flashWright` path.
2. Static identity freeze (default): the idle/static portrait and all seed-derived geometry and palette stay byte-identical. Motion traits derive from unused hash bit-ranges with no new PRNG draws, so `WRIGHT_SPEC_VERSION` stays `wright-geometry-v1`; only the Wright golden fixture's mounted animation frames may be regenerated.
3. Restraint bounds (default): motion keeps rendered geometry inside the existing 100×100 viewBox stroke bounds and holds the 10% red-accent painted-area ceiling at every animated frame; `prefers-reduced-motion` output remains fully static.
4. Acceptance bar (default): automated event-frame determinism + settle-to-rest tests, plus the Builder driving `demo/index.html` at `local:3108` (selecting the Wright variant and sweeping states, capturing frame screenshots as evidence).

## Research

Skills consulted: modern-javascript-patterns

- `src/variants/wright.js` owns the complete Wright pipeline and currently carries the placeholder motion: `poseWright` returns `{ lift, shear, pulse }` (a single `working` pose plus a zero pose), `animateWright` drives those fields per state, and `paintWright` reads `pose.lift`, `pose.shear`, and `pose.pulse`. The `wright` descriptor binds all eight hooks (`derive`, `describe`, `prepare`, `geometry`, `pose`, `animate`, `paint`, `flash`) with `label: 'Wright Scaffold'` and `spec: WRIGHT_SPEC_VERSION`.
- `src/core.js` owns the runtime state machine: `STATES = ['idle', 'working', 'waiting', 'done', 'error', 'thinking', 'sending', 'receiving', 'sleeping']` plus an internal `settling` state. It calls `variant.animate(pose, ctx)` each frame with `ctx = { params, state, dt, t, transientT, rest }`, switches `settling` back to `idle` when `animate` returns `ctx.rest`, and applies the `flash`/`lighten`/`shake` envelope for `done`/`error`/`sending`/`receiving` through `variant.flash(...)`. Mounting in `working` uses `variant.pose(p, 'working')` as the initial pose; reduced-motion and SSR render the static rest pose.
- `src/variants/orbit.js` and `src/variants/ncube.js` show the established pattern for this exact work: motion traits (`dir`, speeds, phase) are derived in `prepare*` from disjoint bit-ranges of `params.hash` with **no new PRNG draws**, so `derive*` output and the static portrait stay frozen; every non-idle state eases toward a target and `settling` returns `rest` when within epsilon. `poseWright` should follow the same discipline.
- `src/variants/registry.js` and `src/variants/validate.js` define the pose/animate/paint/flash contract: pose objects are treated as immutable (`animate` returns a new object), `flash` returns `{ hue?, lighten?, shake? } | null`, and `validateVariant` probes determinism and SSR-safety over `PROBE_STATES`.
- `paintWright` emits semantic layers in stable order with `data-wright-layer` attributes (`primary-mass`, `horizontal-plane`, `grid-module`, `decoration`, `accent`), and `resolveWrightRoles` enforces ≥3:1 WCAG contrast on final emitted colors after lighten/flash. `paintedAreaMetrics` measures the red accent as stroke footprint against total painted area. The palette feature froze these invariants; motion must preserve them at every animated frame.
- Golden regression infrastructure: `test/helpers/golden.js` maps the `wright` id to `test/fixtures/golden-wright-v1.json` and captures static SVG plus mounted frame hashes (`captureMountedScenario` drives `working` then all public states), verified by `scripts/check-variants.mjs` and regenerated by `scripts/generate-golden.mjs`. Changing motion changes only the fixture's `mounted` section; the `static` section must stay identical.
- Full-repository lint baseline: command `none configured` (AGENTS.md declares `Lint: none`, and `package.json` has no lint script); exit status `N/A`; findings: no lint baseline exists, so nothing to overlap. Because there is no lint command, changed JavaScript is gated by `node --test test/wright.test.js` and the maintainer gate `npm run verify` (`npm test` plus `npm run check:variants`). Baseline on 2026-09-21: `npm run verify` exited 0 (180 tests pass; `contract`, `exports`, `types`, `pack`, `goldens` all ✓).

## Approach

- In `src/variants/wright.js`, replace the placeholder `{ lift, shear, pulse }` pose vocabulary with a frozen Wright motion pose. Recommended shape (the Builder may name fields as long as the invariants and tests below hold): `{ illuminate, panelPulse, settle }` — `illuminate` is the position/strength of an illumination sweep across the horizontal planes or grid modules, `panelPulse` is the grid-panel pulse strength, and `settle` is a small structural vertical offset used for settle/reconstruct. `poseWright(params, 'idle')` returns the all-neutral rest pose so static rendering stays byte-identical.
- Map each public state to a distinct, restrained motif: `working` = steady illumination sweep plus gentle panel pulse; `waiting` = slow single illumination drift with minimal pulse; `thinking` = sequential panel-illumination cascade (scanning); `sleeping` = very slow dim breath (core already drops opacity to 0.7); `sending`/`receiving` = transient outward/inward illumination burst decaying with `transientT`; `settling` = structural settle/reconstruct easing every field back to `rest` and returning `ctx.rest` by identity when settled. `done`/`error` stay flash-driven via `flashWright`.
- Derive tunable motion traits (sweep direction, phase offsets, speed bases) in `prepareWright` from disjoint bit-ranges of `params.hash`, exactly as `orbit`/`ncube` do — **no new PRNG draws**, so `deriveWright` output, `WRIGHT_DRAW_ORDER`, and `WRIGHT_SPEC_VERSION` (`wright-geometry-v1`) are unchanged. Keep all pose objects frozen and have `animateWright` return new objects without mutating input.
- Extend `paintWright` to interpret the new pose: apply bounded illumination lightening to the lit plane/module, per-module panel-pulse stroke/brightness modulation, and the structural settle offset to the structural layers — preserving layer order, `data-wright-layer` attributes, and byte-identical rest rendering. Ensure final emitted colors keep ≥3:1 contrast, geometry stays inside the viewBox stroke bounds, and the red accent stays ≤10% painted area at every frame.
- Extend `test/wright.test.js` with: event-frame determinism (animate N frames per state and compare runs), settle-to-rest identity for every non-idle state, per-state distinctness of the emitted frame, byte-identical `deriveWright` for the geometry/palette lock seeds, viewBox/red-ceiling/contrast invariants across animated frames, and a reduced-motion static check. Update the existing "scaffold hooks animate deterministically" test to the new pose vocabulary.
- Regenerate the Wright golden entry only: run `node scripts/generate-golden.mjs`, then confirm the non-Wright fixtures (`golden-v1.json`, `golden-ncube-v1.json`, `golden-orbit-v1.json`) are byte-identical to `origin/main` and the Wright fixture's `static` section is unchanged (only `mounted` hashes differ).
- Keep the lint decision explicit: no lint command exists, so the focused `node --test test/wright.test.js` is the per-file behavior gate and `npm run verify` is the full repository gate. The final diff changes only `src/variants/wright.js`, `test/wright.test.js`, `test/fixtures/golden-wright-v1.json`, and the delivery artifacts in this directory.

## Risks

- Motion traits could accidentally perturb frozen geometry/palette identity. Mitigation: derive traits from disjoint hash bit-ranges only, assert byte-identical `deriveWright` for the geometry/palette lock seeds (`maya`, `wright-family-5`, `wright-family-0`, `wright-palette-*`), and keep the golden `static` section unchanged.
- Illumination or panel-pulse rendering could push an emitted structural color below the 3:1 contrast floor or inflate the red accent. Mitigation: apply illumination as bounded lightening through the existing role-resolution path, and re-run the contrast and 10%-red-ceiling assertions over animated frames (not just the idle pose).
- Motion could leave geometry outside the viewBox or never settle, leaking `NaN`/`Infinity` or drifting forever. Mitigation: clamp every offset to the stroke bounds, freeze poses, and require `animateWright` in `settling` to return `ctx.rest` by identity within a bounded number of frames.
- A concurrent delivery may start after planning and touch `src/variants/wright.js` or `test/wright.test.js`. Mitigation: re-list open PR files and merge `origin/main` before every push; sequence after any newly overlapping slug if integration would combine unstable Wright behavior.
- The golden fixture is easy to regenerate too broadly. Mitigation: after regenerating, diff the non-Wright fixtures and the Wright `static` section against `origin/main` and commit only the Wright `mounted` change.
- The repository has no lint command. Mitigation: require focused Node tests for every motion invariant and a final `npm run verify`; any newly introduced lint configuration is outside this feature and cannot be silently substituted.

## Out of scope

- Any change to `deriveWright`, `WRIGHT_DRAW_ORDER`, geometry grammar, palette families, or `WRIGHT_SPEC_VERSION`.
- Changes to `demo/`, README, React integration, type declarations, or any non-Wright variant (`polyhedron`, `ncube`, `orbit`).
- Small-icon geometry/LOD tuning (owned by `wright-variant-legibility-tuning`) and regression-fixture expansion beyond the Wright golden update (owned by `wright-variant-regression-suite`).
- New public options, exports, or APIs; reproduction of any specific historical artwork, building, textile block, or stained-glass design.
