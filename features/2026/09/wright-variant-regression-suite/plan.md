# Wright variant regression suite

## Problem

The Wright variant family is implemented and merged, but its regression coverage does not yet match the other built-in families. `src/variants/wright.js` is guarded by unit tests in `test/wright.test.js`, and `test/fixtures/golden-wright-v1.json` is wired through `test/helpers/golden.js` and `scripts/check-variants.mjs` — but the golden fixture only captures the five generic seeds shared by every family (`maya`, `build-bot-7`, `Alice@X.com`, `Ada Lovelace`, `demo-agent`), so none of the Wright-specific geometry families, palette families, or hybrids are locked. Plain `npm test` also has no Wright golden test (`test/golden-v1.test.js`, `test/golden-ncube.test.js`, `test/golden-orbit.test.js` exist; `test/golden-wright.test.js` does not), so Wright golden freshness is only enforced by `npm run check:variants`. Finally, every family except Wright has an advisory performance benchmark (`scripts/measure-ncube.mjs`, `scripts/measure-orbit.mjs`); Wright has none.

This plan implements the `wright-variant-regression-suite` member of the [Frank Lloyd Wright variant breakdown](../../../../initiatives/2026/09/frank-lloyd-wright-variant/breakdown.md#wright-variant-regression-suite), whose brief is: "Lock behavior against regressions and ensure existing variants remain byte-identical and unaffected." It extends deterministic/golden/performance coverage for the Wright family with representative seed sets and event-frame stability checks, while leaving every existing variant fixture byte-identical and never changing Wright derivation, motion, legibility, or palette behavior.

## Decisions

The user answered all three clarifying questions, accepting the recommended option for each:

1. Performance coverage (recommended): add `scripts/measure-wright.mjs` as an advisory benchmark mirroring `measure-ncube.mjs`/`measure-orbit.mjs`, with recorded evidence under this feature's `evidence/` directory; no timing assertions in `npm test` or CI (avoids flaky shared-runner gates).
2. Golden seed sets (recommended): extend golden capture with representative Wright seeds — one per geometry family, one per palette family, plus a hybrid — regenerating only `test/fixtures/golden-wright-v1.json` and keeping `golden-v1.json`, `golden-ncube-v1.json`, and `golden-orbit-v1.json` byte-identical.
3. Event-frame stability (recommended): add a dedicated hash-locked event-frame stability test (per-state/per-frame determinism + settle-to-rest) over representative Wright seeds, and include those seeds in the mounted golden scenarios.

## Research

Skills consulted: modern-javascript-patterns (Node.js ESM + testing); vercel-react-best-practices not applicable (no React code changes).

- `src/variants/wright.js` owns the complete Wright pipeline and is registered as the built-in `wright` id through `src/variants/index.js`. Its frozen constants (`WRIGHT_SPEC_VERSION`, `WRIGHT_FAMILIES`, `WRIGHT_DRAW_ORDER`, `WRIGHT_LAYER_LIMITS`, `WRIGHT_PALETTE_FAMILIES`, `WRIGHT_PALETTES`, `WRIGHT_CONTRAST_PAIRS`, `WRIGHT_RED_AREA_CEILING`, `WRIGHT_SMALL_SIZE`, etc.) and the `derive`/`describe`/`prepare`/`geometry`/`pose`/`animate`/`paint`/`flash` hooks are all in place and must not be modified by this feature.
- `test/wright.test.js` already covers grammar contract, derivation determinism, geometry hierarchy, size legibility, palette roles/contrast/red-area ceiling, motion determinism, event-frame determinism across `PROBE_STATES`, viewBox bounds, contrast across animated frames, and settle-to-rest identity. Representative lock seeds used there: `wright-family-1/5/3/0` (the four geometry families), `wright-palette-1/11/0` (the three palette families), and `wright-hybrid-<n>` (hybrids with `secondaryFamily !== null`).
- `test/helpers/golden.js` maps family → fixture via `FAMILY_FIXTURES` (`wright` → `golden-wright-v1.json`) and `captureGolden({ variant })` builds `{ static, mounted }` from shared `STATIC_SEEDS` (5 generic seeds) × `STATIC_OPTS`, `MOUNTED_SCENARIOS` (4 scenarios), and a reduced-motion capture. The mounted capture drives `working` for 10 frames then 8 public states for 4 frames each, hashing every frame. This shared seed set is why the Wright fixture currently locks only generic seeds.
- `test/golden-ncube.test.js` and `test/golden-orbit.test.js` show the family golden test pattern: assert the fixture's keys equal the registered ids for that family, then re-capture and compare every static key and every mounted frame hash. There is no `test/golden-wright.test.js`, so Wright golden freshness is absent from plain `npm test`.
- `scripts/generate-golden.mjs` regenerates all fixtures; `scripts/check-variants.mjs` `checkGoldens` re-captures every `BUILT_IN_VARIANTS.ids` entry and deep-compares against `fixtureFor(id)`. Both already include `wright`.
- `scripts/measure-ncube.mjs` and `scripts/measure-orbit.mjs` define the performance-benchmark shape to mirror: static SVG byte size + median `paint()` time over 200 calls across seeds, then an animated engine-loop table (working frames, a send burst, settling to rest) reporting median/p95 `animate + paint` ms and the settling frame count, gated `frame gate: pass|fail`. Neither is invoked by `npm test`, `check:variants`, or CI; their results are recorded in feature `evidence/` files and cited from README.
- `.github/workflows/ci.yml` runs `npm ci`, `npm test` (`node --test test/*.test.js`), and `npm run check:variants` (`node scripts/check-variants.mjs`). `npm run verify` = `npm test && npm run check:variants`.
- Full-repository lint baseline: command `none configured` (AGENTS.md declares `Lint: none`, and `package.json` has no lint script); exit status `N/A`; findings: no lint baseline exists, so nothing to overlap. Changed JavaScript is gated by `node --test test/wright.test.js` (plus the new `test/golden-wright.test.js`) and the maintainer gate `npm run verify`.
- Concurrent-delivery check: `gh pr list --state open --json number,headRefName,title` returned `[]` on 2026-09-21 in both repositories — no open delivery branch overlaps `test/helpers/golden.js`, `test/wright.test.js`, `test/fixtures/golden-wright-v1.json`, or the new `scripts/measure-wright.mjs`. Recheck before push and merge `origin/main` as required.

## Approach

- Add `test/golden-wright.test.js` mirroring `test/golden-ncube.test.js`: assert `golden-wright-v1.json`'s keys equal `BUILT_IN_VARIANTS.ids.filter(id => id !== DEFAULT_VARIANT_ID && fixtureFor(id) === 'golden-wright-v1.json')`, then re-capture and compare every static key and every mounted frame hash. This brings Wright golden freshness into plain `npm test`, matching the other three families.
- Extend `test/helpers/golden.js` with a per-variant representative-seed extension (e.g. a table keyed by variant id) so `captureGolden({ variant: 'wright' })` additionally captures Wright-specific static seeds and mounted scenarios: one seed per geometry family (`wright-family-1`, `wright-family-5`, `wright-family-3`, `wright-family-0`), one per palette family (`wright-palette-1`, `wright-palette-11`, `wright-palette-0`), and at least one concrete hybrid seed for which `deriveWright(seed).secondaryFamily !== null`. The shared `STATIC_SEEDS`/`MOUNTED_SCENARIOS` used by the other families stay untouched, so only `golden-wright-v1.json` changes shape. Regenerate with `node scripts/generate-golden.mjs` and confirm the other three fixtures are byte-identical to `origin/main`.
- Add a dedicated event-frame stability test in `test/wright.test.js` over the representative Wright seeds: for every `PROBE_STATES` state, run `animateWright` for a bounded number of frames, assert the frame sequence is deterministic across two runs (deep-equal) and settles to the exact rest pose by identity within a bounded frame count, and assert every painted frame is finite (`/NaN|Infinity/` absent) and inside `WRIGHT_VIEWBOX_BOUNDS`. Include the same representative seeds in the mounted golden scenarios so the golden gate also locks their event-frame hashes.
- Add `scripts/measure-wright.mjs` mirroring `measure-ncube.mjs`/`measure-orbit.mjs`: static SVG byte size and median `paint()` time over 200 calls across the representative seeds (plus the five generic seeds), then an animated engine-loop table (working frames at 30 fps, a send burst, settling to rest) with the same gate columns (median frame ms, p95, settling frame count). Record the run's output to `features/2026/09/wright-variant-regression-suite/evidence/wright-benchmark.txt`.
- Keep the lint decision explicit: no lint command exists, so the focused `node --test test/wright.test.js test/golden-wright.test.js` is the per-file behavior gate and `npm run verify` is the full repository gate. The final diff changes only `test/helpers/golden.js`, `test/wright.test.js`, the new `test/golden-wright.test.js`, the new `scripts/measure-wright.mjs`, `test/fixtures/golden-wright-v1.json`, and the delivery artifacts in this directory.

## Risks

- Extending the golden capture could accidentally regenerate the non-Wright fixtures. Mitigation: the seed extension is per-variant (wright only), and after regenerating, `git diff --exit-code origin/main -- test/fixtures/golden-v1.json test/fixtures/golden-ncube-v1.json test/fixtures/golden-orbit-v1.json` must pass.
- The representative seed list could miss a family or drift from the unit-test lock seeds. Mitigation: pin the list in the plan and reuse the exact seed strings already proven by `test/wright.test.js`; the new golden test asserts the fixture key set matches the registered ids.
- A hybrid seed chosen by name may not actually derive to a hybrid, making that fixture key unrepresentative. Mitigation: the Builder selects concrete hybrid seeds only after confirming `deriveWright(seed).secondaryFamily !== null`, and notes the chosen seeds in the roadmap step.
- Timing measurements are machine-dependent and would be flaky as a CI gate. Mitigation: `measure-wright.mjs` stays advisory (not wired into `npm test`, `check:variants`, or CI); its output is evidence only, matching the ncube/orbit scripts.
- A concurrent delivery may start after planning and touch `test/helpers/golden.js` or `test/wright.test.js`. Mitigation: re-list open PR files and merge `origin/main` before every push; sequence after any newly overlapping slug.
- The golden fixture is easy to regenerate too broadly. Mitigation: after regenerating, diff the non-Wright fixtures against `origin/main` and commit only `golden-wright-v1.json`.
- The repository has no lint command. Mitigation: require focused Node tests for every new assertion and a final `npm run verify`; any newly introduced lint configuration is outside this feature and cannot be silently substituted.

## Out of scope

- Any change to `src/variants/wright.js`, its frozen constants, `WRIGHT_SPEC_VERSION`, derivation, motion, legibility, or palette behavior. If a new test exposes a defect, a separate issue is filed rather than fixing behavior here.
- Changes to `demo/`, README, React integration, type declarations, or any non-Wright variant (`polyhedron`, `ncube`, `orbit`).
- Companion documentation/demo updates (owned by `wright-variant-react-demo-docs`, wave 5).
- Adding timing assertions to `npm test` or CI; new public options, exports, or APIs.
